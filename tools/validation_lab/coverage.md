## 身体の隣接接続の計測範囲

body_executionは入力にモデル・初期状態・初期軌道・両方針・計画要求・外界座標・支持接触・開始日時・更新回数・間隔を保持する。反復ごとに本番の所有者を新設し、身体状態は本番BodyStateAuthorityだけが更新する。時間の進行は単調時計の実測値であり、指定間隔が必ず達成されたとは扱わない。

現在の試験は定型計画の実採用、短い計画遅延との重なり、未構成LLMによる計画失敗中の姿勢更新、終了・期限超過時の回収を確認する。20秒の遅延指定を短時間で取り消す試験は、20秒間の動作継続の証拠ではない。本番BodyRealtimeRuntimeとBodyRealtimeEngineを追加接続し、生成された合成情報を本番の採用検査へ渡す。最新の合成情報・生成回数・採用参照・遅延更新回数も記録する。実測5秒・20秒の待機を最後まで経る試験を別途追加し、その間の姿勢更新・合成情報の反映と待機後の計画採用を確認した。本番の姿勢投影と模擬描画先、記録のHTML表示まで接続した。実際の描画先・全身モデルの可視表示・実LLM・人間による品質確認は未完である。

既存StickAvatarRendererは投影命令を保持する接続であり、画面への可視表示を行わない。これを利用しただけでは棒人間の可視化要件が完了した証拠としない。

#352の任意出力として本番姿勢のHTML可視化を追加。既存の関節座標・末端位置計算から三面図を生成し、観測時刻に沿って記録を切り替える。実ブラウザーで表示・再生・位置変更を確認した。今回の描画確認は簡略化されたbody.d10試験モデルを使用し、全身の見た目や品質確認を代替しない。

ActivityPlanを確定する#361と、ActivityInvocationを受ける#329は存在するが、現行app内では確定計画から要求を構成・投入する入口を確認できない。#334の汎用処理基盤と関連PR #405/#403も確認した。この経路は設計と#361の隣接検証要件に含まれるため、未完として#334へ記録した。検証側で手順選択や命令発行権限、再試行・再計画の判断を補作しない。

活動の評価接続では、確定した実行結果から本番が投影した出来事を変更せずに定型評価へ渡す。後続の状態更新が拒否された場合も、実行結果・出来事・効果参照を結果へ保持し、失敗した段階を記録する。目標の自動完了や後続判断の代行は行わない。

## 実行判断・人物表現とゲームの並行接続

既存の `executive_target`、`speech_generation_target`、`game_monitor_target` を `ParallelCase` の3入力として接続した。本番の ExecutiveDeliberator と CharacterLanguageRealizer が公開 LLM 接続を同時に待つ間、GameSkillRuntime は独立して進行する。

実測20秒の通常終了、待機中の取消、待機後の状態版不一致の3試験が成功した。20秒条件では毎秒の全20観測区間で状態版が増加し、各区間が両 LLM 待機区間の内側にあることを確認した。終了後のゲーム未完了処理数は0。取消時には両接続の待機も回収する。古い実行判断は本番の確定検査で拒否されても、人物表現とゲームの完了証拠は保持される。

これは三つの既存所有者の並行動作を検証するもので、実行判断からゲーム戦略を新規決定する結合ではない。模擬 LLM・模擬ゲームを使い、実 LLM、実ゲーム、会話品質、全体の継続運転の合格へ昇格しない。既存の第19節の要件を扱い、目標対象外 #586 の性能改善は行っていない。

状態更新後の評価事実接続は #327 / #401 の PR #587、独立レビューがPASSの対象HEAD `bfcabea4f6d047c00aae77c778fc76b0c680c14b`を、合流点 `8a8b4cecdc77225139e3af836d71b6c8ff62ebd2`で本流へ採用済みである。#352はこの本流を基底とし、`InternalStateReducer.commit_with_facts`が同時確定する状態と評価事実を本番の実行判断へ渡す隣接接続を追加済みである。元候補の基底版を保持し、現在状態・周辺文脈との照合は本番所有者へ委譲する。検証基盤の追加は#352の製造範囲であり、実LLM・本体構成を用いた全体結合と計画から活動命令への未確定境界は残る。


## 永続化対象の訂正

本番DBは PostgreSQL である。PR #458 のレビュー comment 5419242845 でも、SQLite 単独の本番採用を不可と明記している。今回追加した SQLite 接続し直しの試験は本番永続化の証拠にできないため作業成果から除外した。既存のメモリ内の単独・隣接検証を保持し、本番 PostgreSQL 接続は #359 の未完実装として扱う。#352 の完了記録へ昇格しない。

共有待ち行列の隣接検証として`speech_queue_target`を追加した。複数の準備済み候補を同じ本番所有者へ登録し、優先順位・容量超過・現在状態の再照合・連続提示・取消を接続する。後続候補の再照合失敗でも先の提示完了記録を保持する。生成始点の全経路や人間による発話品質の合格ではない。

生成から共有実行基盤への型付き接続は`SpeechPreparationSession`で追加した。実際の発話生成・意味検証・候補確定を通った二候補が、同じ本番待ち行列から現在状態照合・提示へ進む試験が成功した。並行候補の先行合成枠共有と一候補の取消分離も確認済み。過去の準備済み入力だけの証拠と区別し、実提供先・提示中の追加投入・割込み・継続運転の未完条件を維持する。

共有実行基盤の提示中に次候補の生成・意味検証・準備確定・待ち行列投入が完了する正常経路と取消経路を確認した。実測区間の包含を検査しており、ログ順だけの推測ではない。提示の割込み方針と実環境品質の全体確認は残る。

`tests/system_integration/test_core_executive.py`は、本体の定型評価・注意選択を既存の実行判断所有者へ接続する。供給する根拠・能力・前提条件・独立した必須要件は模擬読取境界を用い、応答後の再取得、各変更の拒否、同じ契機の二重確定防止、取消・再取消の回収を検証する。模擬境界を本番供給元の登録完了とは扱わず、具体的な根拠供給元・全役割起動・判断後の全分岐・実LLMと実発話品質は後続に残す。

### 実行判断の本体実行への登録

`tests/system_integration/test_core_executive_runtime.py`は、実際の判断所有者を既存の本体実行基盤へ登録し、判断待機中の独立した前景処理の継続、相関・元イベントの不一致拒否、古い注意の実行抑止、受付上限、正常停止時の子タスク回収と取消結果の取得を検証する。根拠・LLM提供先は模擬であり、具体的な供給元登録・全役割起動・判断後の分岐・本体全体の品質は未完了である。
