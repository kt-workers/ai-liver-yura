# 製品の入口を使う検証基盤

Issue #352の共通基盤です。製品の意味判断や失敗処理は変更せず、登録した接続から本番の公開入口を呼びます。

## 実行例

リポジトリのルートで、既存依存を導入済みのPython 3.10から実行します。

```sh
python -m tools.validation_lab --output /tmp/yura-game-validation --repeat 3
```

既存ゲーム実行基盤に模擬の戦術判断と操作先を接続し、別の処理が待機している間に操作が3回適用されることを検証します。実ゲームや資格情報は使用しません。出力先には既存のresult.jsonとresult.mdがない場所を指定してください。

JSONとMarkdownは同じ実行結果の投影です。各反復の操作・適用報告、単調時計で測った処理区間、製品のcommit SHA、検証範囲、入力のリビジョンを保持します。製品ソースに未記録の変更がある場合は起動を拒否します。

## 現在利用できる範囲

- 検証条件と登録済み対象の契約・入力・提供サービス方針の照合。
- 反復、時間制限、取消、所有する子処理の回収、証拠保持数と書出し容量の上限。
- 指定した接続境界での遅延注入と、実測した区間の重なり。
- 入力意味解析、発話生成、独立した意味観測、発話計画との照合の接続境界での遅延と利用不可・時間切れ・役割取消の失敗注入。未登録の注入先は実行前に拒否。
- 提供サービス側の既存の安全な診断を実行単位で収集し、容量超過時の省略件数も保持。
- 人間の項目別評価と匿名比較の対応管理。全候補の評価後に出典を開示し、人間の評価で機械判定を書き換えない。
- 既存InputMeaningInterpreterを利用する入力意味解析の単独接続。
- 既存DeepAppraisalInterpreterとExecutiveDeliberatorを利用する深い状況評価・実行判断の単独接続。LLM境界の観測と注入、待機後の製品による世代照合を通す。
- 検証専用GoalCommitmentStoreによる目標・約束の更新と、AttentionCoordinatorによる判断開始情報の引渡しを記録する単独接続。
- 既存GoalPlannerとSpeechSemanticsPlannerを呼ぶ目標計画・発話意味の単独接続。定型経路とLLM経路の選択は製品に委譲する。
- 既存BodyMotionPlannerとBodyMotionPlanAuthorityを呼ぶ身体運動計画の単独接続。
- 既存StreamingSubsystemRuntimeを呼び、型付き配信操作と効果の報告を保持する単独接続。
- 既存GameSkillRuntimeを利用する模擬ゲームの単独検証コマンド。
- 既存MemoryStoreAuthorityの書込・検索を、反復ごとに分離した検証用保存先で実行する単独接続。順位付け方針も入力に記録し、保存判断・根拠・検索結果を保持。
- 既存ReflectionCoordinatorとReflectionCandidateAuthorityを使う振り返りの単独接続。候補生成・根拠観測の遅延、製品の採用・拒否結果、運用観測、終了時の所有タスク回収を記録。
- 確定済みの発話意味を入力し、既存CharacterLanguageRealizerの生成結果をSemanticVerifierとSpeechPerformancePlannerへ渡す隣接接続。意味検証と発話表現計画の処理区間、および取消時の子処理回収を記録。
- 入力由来の人間向け説明と製品入力の分離。機械判定から人間の評価を作らず、UNRATEDを保持。

## 証拠の限界

入力意味解析、深い状況評価、実行判断、模擬ゲーム、記憶の保存・検索、振り返りはISOLATION、発話生成・意味検証・発話表現計画の接続はADJACENTです。INTEGRATEDや実機の品質確認へ昇格できません。模擬ゲームで使う遅い相手処理は、実Executiveや実TTSの結合を証明しません。

入力意味解析の対象接続は、製品が返した成果を記録します。意味の正否を検証基盤が独自に決めないため、その機械判定はNOT_RUNです。

発話の隣接接続も機械判定はNOT_RUNです。製品が決定した意味採用結果と発話表現計画をそのまま記録します。生成前の入力には発話意味、人物定義、声の特性、表現状態を含めます。起動コードが登録した製品接続を使い、反復ごとに呼出し識別子を分けます。音声合成と提示へ継続する場合は、後述の候補準備と音声合成の設定を使います。この接続の試験だけでは#434の正式な人間による会話品質評価の証拠にはなりません。

記憶の単独接続はMemoryLabCaseの書込要求と検索要求を、memory_targetから既存の保存判断主体へ渡します。指定した順位付け方針が記録した入力と異なれば実行を拒否します。保存先は既存InMemoryMemoryRepositoryを各反復で新規生成します。検索順位や重複判断を検証側で作らず、その機械判定はNOT_RUNです。本番の PostgreSQL 永続化と意味検索索引は残る検証範囲です。振り返りとの隣接接続は後述します。

振り返りはReflectionLabCaseに元の状況と運用・採用方針を記録し、reflection_targetへ既存の候補生成・根拠観測の接続を渡します。reflection.proposalとreflection.supportで遅延を指定できます。採用・拒否は製品が判断し、検証側は記憶への提出や関係付けを独自に決めません。保存済みの記憶へ候補をつなぐ経路と、前景の会話との結合は残る検証範囲です。

深い状況評価はAppraisalLabCase、実行判断はExecutiveLabCaseで製品入力を指定します。それぞれappraisal_target、executive_targetへ既存LLM接続・現在状態の読取接続・製品方針を渡します。製品自身の要求組立てによって入力を照合し、appraisal.llm、executive.llmの境界で遅延・失敗を注入できます。機械判定はNOT_RUNです。状態変更候補を運用中の状態へ適用したり、採用済み判断を実際の行動として実行したりしません。速い状況評価、状態更新、後続実行までの結合は残る範囲です。

登録済み接続は公開可能な型付き入出力だけを投影してください。既知の秘密項目名の拒否は補助検査であり、任意の文字列に秘密がないことを保証しません。提供サービスの設定、SDK応答、生の例外、無関係な会話履歴を投影元へ渡してはいけません。

任意のファイルから関数名・モジュール名・シェル操作を解決する入口はありません。対象接続は信頼済みの起動コードが登録し、自身が生成する製品の実行基盤・クライアントも終了時に回収します。

## 発話接続と診断の登録

`make_speech_bindings`へ既存のLLM接続、現在状態の読取接続、製品方針、発話表現計画器を渡します。既存の判断主体を内部で構成し、次の段階だけを注入可能として登録します。

| 段階 | 対象 |
| --- | --- |
| `speech.character.llm` | 発話文の生成 |
| `speech.blind.llm` | 発話計画を見ない独立した意味観測 |
| `speech.relation.llm` | 発話計画と観測済み発話の照合 |
| `input_meaning.llm` | 入力意味解析の単独接続 |

注入する失敗は既存のLLMRoleResultです。製品が例外で終了した場合はPRODUCT_FAILEDとして呼出し段階を記録し、詳細原因は推測しません。検証側の接続構築・投影・資源回収に失敗した場合はHARNESS_FAILEDです。

実行固有の診断先が必要な場合は、接続の代わりに`LabLLMPortFactory`を渡します。その構築関数はRunContextを受け取り、既存OpenAIResponsesAdapterの`diagnostic_sink`へ`context.diagnostics`を渡せます。検証が新しく生成して所有するクライアントは`context.add_cleanup`へ非同期の終了処理を登録します。共有クライアントの終了処理は登録しません。

所有する子処理の回収後に、登録と逆の順序で資源を終了します。登録数はmax_tasks、各終了処理の待機時間はtimeout_secondsで制限し、一つの終了処理が失敗しても残りを回収します。失敗の本文は書き出しません。

## #352の残工程

配信はStreamingLabCaseに能力情報・型付き要求の列・観測日時を記録し、streaming_targetへ既存の提供サービス接続を渡します。streaming.providerで遅延を指定できます。要求は順に実行し、非成功の報告を受け取ったら後続要求を実行しません。効果の未適用・不明・曖昧さは製品の報告どおりに残します。ISOLATION、機械判定NOT_RUNであり、自然文の言い換え解釈、コメントの集中入力、外部状態観測の整合は別の検証範囲です。

身体運動計画はBodyPlanningLabCaseに身体モデル・状態・表現・制約・能力を含む製品入力を記録し、body_planning_targetへ既存LLM接続・現在状態読取・製品方針を渡します。body.planning.llmで遅延・失敗を注入できます。ISOLATION、機械判定NOT_RUNであり、確定した計画を身体の実時間処理へ渡す結合や姿勢の描画は含みません。

目標計画と発話意味はPlanningLabCaseに製品の状況入力と作成日時を記録し、goal_planning_targetまたはspeech_semantics_targetへ既存の現在状態読取・製品方針・LLM接続を渡します。必要に応じて容量方針の現在世代の読取先も渡せます。goal_planning.llm、speech_semantics.llmで遅延・失敗を注入できます。ISOLATION、機械判定NOT_RUNであり、確定した計画の実行や後続の発話生成はまだ含みません。

目標・約束はGoalCommitmentLabCaseに初期状態と採用済み実行判断を指定し、goal_commitment_targetで既存の更新入口へ渡します。注意はAttentionLabCaseに割当方針と入力手順を指定し、attention_targetで既存AttentionCoordinatorへ渡します。どちらもISOLATION、機械判定NOT_RUNです。反復ごとに検証専用の状態所有者を生成し、運用中の状態は更新しません。注意が引き渡した判断開始情報は記録するだけで、実際の実行判断へはまだ接続しません。

他の所有者への接続と各接続での失敗注入・運用診断、匿名比較の評価操作、音声合成と提示を含む発話全体・身体・記憶・配信の隣接／結合検証を順次追加します。現在の検証成功は#352全体や#360の完了を意味しません。

## 保存済み証拠への評価入力

実際に評価する人が、端末で次を実行します。

```sh
python -m tools.validation_lab.review /tmp/yura-game-validation/result.json \
  --output /tmp/yura-game-review \
  --evaluator 評価者の識別子 \
  --dimension 状況説明の分かりやすさ
```

入力に由来する状況説明、型付き入力、実際の出力を表示した後、各項目へ1（合格）、2（不合格）、3（対象外）を入力します。評価項目は`--dimension`で複数指定できます。空欄を合格とは扱いません。項目の入力中にqを指定するか、入力終了・割込みで中断すると、評価済み記録を保存しません。

最後にコメントを入力すると、新しい保存先へreview.jsonとreview.mdを作成します。元の検証結果を全体のまま保持し、その外側へ実際の評価者・項目別評価・コメント・日時を追加します。機械判定や元のUNRATEDを書き換えません。元ファイルのSHA-256は評価対象との対応付けに使い、生成工程の再検証や正当性の認定には使いません。

この操作で記録する範囲は診断評価（diagnostic_human_review）です。#434の正式な会話品質評価や実機の完成確認へ自動昇格しません。評価前には機械判定と出典の見出しを表示しませんが、実入力・実出力を編集しないため、完全な匿名比較を保証する操作ではありません。

読取と書出しは各1MB、コメントは8KB、項目は16件までです。重複JSON項目、非有限数、既知の非公開項目、状況説明や実出力がない証拠を拒否します。提供サービス設定や無関係な会話履歴を含むファイルは入力しないでください。

## 提供サービスの順序制御の検証

ProviderSchedulingCaseには実際のRuntimeWorkItem、処理列・順序制御・終了の方針を渡します。provider_scheduling_targetは本番RuntimeCoordinatorへ要求を投入し、受付結果、処理結果の区分、受付から処理開始までの時間、接続呼出し時間を記録します。接続呼出し時間にはprovider.invokeで指定した検証用遅延が含まれ、HTTP通信だけの時間ではありません。

拒否された要求と入れ替えで除外された要求の結果を待ち続けません。提供サービスの例外本文は書き出さず、例外終了でも呼出し時間を保持します。COMPLETEDは計測実行の完了を表し、各要求の成功を意味しません。各要求の状態を別に確認してください。範囲はISOLATION、機械判定はNOT_RUNです。要求を統合するCOALESCEは統合処理が未接続のためBLOCKED_UPSTREAMとなります。実際の各所有者からの要求との結合は未実装です。

## 発話意味の生成から人物表現への接続

SpeechGenerationCaseには発話意味の入力、人物表現の定義、制約、優先順位、割込み方針、生成日時を渡します。speech_generation_targetは本番SpeechSemanticsPlannerで生成したSpeechSemanticPlanを、そのままCharacterLanguageContextSnapshotへ渡して本番CharacterLanguageRealizerを呼びます。計画、後段へ渡した実入力、発話結果を保存します。前段が失敗した場合は後段を呼びません。

範囲はADJACENT、機械判定はNOT_RUNです。発話意味の定型経路とLLM経路を製品の判断どおりに使用します。実際の音声合成・提示までの結合や、過去の表現を使った反復回避はこの接続では未検証です。

人物表現の生成関数に代えてSpeechAdjacentBindingsを渡すと、対象名speech_generation_chainとして、生成済み発話を意味検証と発話表現計画へ渡します。この二つの後続処理は並行して実行します。SpeechGenerationCaseのvoice_styleとexpressionも実入力として保存します。意味検証の採否と実行完了を区別し、採用拒否でも診断用の表現計画結果は保持します。音声提示を許可する判断は行いません。両方へ同一の発話を渡し、取消時には待機処理を回収します。

## 発話の提示入口の検証

SpeechPresentationCaseには準備済み候補、提示前の現在状態、運用方針を渡します。speech_presentation_targetは本番SpeechRuntimeとSpeechPresentationExecutorで提示前照合と提示結果の受入れを実行し、命令・受入れ済み報告・終端報告・候補の最終状態を記録します。報告数はmax_intervalsを上限とします。取消時には提示処理を回収します。検証内の時計は入力した現在状態の観測日時に固定します。

範囲はISOLATION、機械判定はNOT_RUNです。提示先は起動側が渡します。模擬の文字提示報告を実音声の提示証拠へ昇格しません。生成からの結合には、後述の候補準備・音声合成の組込みを使用します。実際の可聴音声の確認は別途必要です。

## 音声合成の公開入口の検証

TTSSynthesisCaseには発話と表現計画を含むTTSSynthesisRequest、変換方針、運用方針、再試行方針を渡します。tts_synthesis_targetは本番TTSProviderAdapterを呼び、型付き結果と公開音声参照、時刻情報、試行回数を保存します。提供サービスの生応答や内部音声参照は保存しません。tts.providerで遅延を指定できます。時計は要求日時を起点に実際の経過時間で進み、期限後の応答の不採用も製品が判断します。

範囲はISOLATION、機械判定はNOT_RUNです。模擬音声参照を使った試験を実際の可聴音声・提示・人間の評価へ昇格しません。音声資源の内部参照表は反復内の接続が所有し、この単独接続は書き出した公開参照から後で再生する機能を提供しません。生成結果や提示との結合には、後述の隣接接続を使用します。

## 合成音声から提示への結合

AudioPresentationCaseに対応する合成要求と提示候補を渡すと、audio_presentation_targetは合成結果の公開音声参照を提示入口へ渡します。提示先の生成関数には同じ資源参照表を渡し、提示中に参照を解決できるようにします。合成失敗時は提示を呼びません。提示前の現在状態照合は本番の発話実行基盤が行います。終了時は準備済み音声の破棄手順を通し、検証が所有する参照表を無効化します。提供サービス側の実ファイルの削除機能ではありません。

範囲はADJACENT、機械判定はNOT_RUNです。入力の候補準備と採用確認は検証条件が与えるため、発話生成からの全経路の証拠にはなりません。模擬音声と模擬提示での試験を、実際の可聴音声・人間の評価へ昇格しません。

## 生成結果から候補準備への接続

SpeechAdjacentCaseまたはSpeechGenerationCaseのpreparationにSpeechPreparationSettingsを指定すると、生成した発話・表現計画と本番の意味検証が確定した採用結果を、本番SpeechRuntimeの候補登録と世代付き確定処理へ渡します。運用方針・優先順位・前提条件・提示方式は入力として記録します。候補の準備完了または採用拒否は実行基盤が決定し、prepared_candidateへ保存します。

PREPAREDは提示可能を意味しません。待ち行列への移行を指定しない場合は、候補準備と指定された音声合成までで、提示には進みません。意味検証と表現計画への接続を省略した候補準備は登録時に拒否します。

SpeechPreparationSettingsのqueue_for_revalidationを有効にする場合は、SpeechAdjacentBindingsのrevalidationへSpeechRevalidationStatePortを接続します。生成候補を本番の待ち行列へ入れ、取り出してREVALIDATINGへ移行した後でcurrent_stateを呼びます。取得した状態と受付結果を記録します。speech.revalidation_stateで遅延を指定できます。validate_for_presentationを指定しない場合は取得結果を記録してREVALIDATINGに留まります。指定した場合は本番SpeechRuntime.revalidate_currentへ最新状態を渡します。本番の提示確定と共用する照合が成功した場合だけREADY_TO_PRESENTへ進みます。提示確定時にも同じ照合を再実行します。

## 生成候補から同じ実行基盤での提示

SpeechPreparationSettingsのpresent_after_validationを有効にし、SpeechAdjacentBindings.presentationへ提示先を渡すと、再照合済み候補を同じSpeechRuntimeで提示確定し、終端報告まで待ちます。候補を別の実行基盤へ再登録しません。採用拒否された発話はこの経路へ進まず、提示中の取消は所有する処理へ伝わります。

生成から文字提示までの模擬結合試験を用意しています。これは実LLMの品質、音声合成を含む全経路、実際の可聴音声、人間の評価を証明しません。音声合成を含む結合については、次節の設定を使用します。

## 生成経路への音声合成の組込み

SpeechPreparationSettings.audioにGeneratedAudioSettings、SpeechAdjacentBindings.audioにGeneratedAudioBindingsを渡すと、採用済みの生成発話と表現計画から合成要求を構築し、同じ候補へ音声参照を確定します。その後に待ち行列から最新状態を取得して照合し、提示を行います。既定構成では採用拒否時は合成せず、合成失敗時は失敗状態を全体の実行結果へ引き継ぎます。合成後の状態変更も提示前に拒否されます。

既定の開始方式は採用後の合成です。全段階を記録するため、結合試験ではmax_intervalsを32に明示しています。模擬音声と提示報告を使う試験は実音声品質や正式な人間の評価の証明ではありません。

## 複数の本番接続の並行実行

ParallelCaseに各対象のLabRunSpecとValidationFixtureをParallelInputとして並べ、parallel_targetへ登録済み対象を渡すと、各検証を同時に実行します。親の範囲はSYSTEM_SLICEで、子のISOLATION・ADJACENTなどの範囲、出典、入出力、時系列、判定をそのまま保持します。親の機械判定はNOT_RUNで、子の成功から品質合格を推定しません。

max_tasksとmax_intervalsは子の数で分割します。発話とゲームの結合試験では親を8処理・64区間とし、各子へ4処理・32区間を割り当てています。親の取消では子の検証を回収します。同じ製品のリビジョンの対象だけを登録でき、並行対象の再帰登録は拒否します。

模擬音声合成を待つ実際の発話経路と、本番ゲーム実行基盤の操作3回が実測で重なることを確認する試験があります。これは長時間の安定性、実ゲーム操作、音声品質の証明ではありません。

## 振り返りから記憶への接続

ReflectionLabCase.memoryにReflectionMemorySettingsを指定すると、対象名reflection_memoryで、振り返りが確定したValidatedMemoryCandidateをそのままMemoryWriteRequestへ渡します。保存の判断は本番MemoryStoreAuthorityが行います。保存要求・結果と、指定した検索条件による検索結果を記録します。拒否された振り返り候補は保存しません。

範囲はADJACENT、機械判定はNOT_RUNです。各反復には専用のメモリ内保存先を作成します。本番 PostgreSQL への永続化・索引更新、既存記憶への関係指定、前景処理との長時間並行性は別の確認範囲です。関係の提案を検証側の判断で確定関係へ変換しません。

### 振り返り待機中の発話提示

`test_parallel_reflection_speech.py`では、`parallel_target`へ振り返り・記憶の接続と音声付き発話生成の接続を登録する。振り返りの提案提供先を待機させ、その待機を解除する前に、本番の発話生成・採用・合成・再照合・提示が完了することを確認する。発話の各実処理区間が振り返り待機区間内に収まることを時系列で照合する。全体取消では振り返りの所有処理と発話の音声参照を回収する。

同期制御による短い試験に加え、提案提供先を実時間で20秒遅延させる条件でも確認する。模擬提供先を使った確認であり、継続的な長時間運転と実音声の品質確認は未実施である。

### 匿名比較の端末評価

実行済みの`ValidationRunResult`を保持する`BlindComparison`へ、`tools.validation_lab.blind_review.evaluate_blind`を接続する。端末で各候補の入力状況・型付き入力・実出力を確認し、全評価項目へ入力する。全候補の評価が終わった場合だけ対応表を返す。`save_blind_review`は完了を再確認し、新しいディレクトリへJSONとMarkdownを保存する。出典・元結果・機械判定は保持する。途中で`q`を入力した場合は対応を開示せず、同じ比較オブジェクトから未評価候補の入力を再開できる。

```python
from tools.validation_lab.blind_review import evaluate_blind, save_blind_review

# comparisonは本番接続の実行結果から作成済みのBlindComparison。
evaluate_blind(comparison, evaluator_id="実際の評価者の識別子")
save_blind_review(output_directory, comparison)
```

比較作成時の`identity_labels`には、隠すモデル名などの識別表記をすべて登録する。実行識別子と提供サービス方針の参照は自動で登録する。これらが表示対象へ埋め込まれている場合は、元候補を加工せず表示を拒否する。未知の別名や文章内容からのモデル推測まで匿名性を保証するものではない。保存済みJSONからは次のコマンドで比較を開始できる。実際の評価者による品質確認は未実施である。

```sh
python -m tools.validation_lab.blind_review result-a.json result-b.json \
  --output comparison-review --assignment comparison-001 --seed 42 \
  --evaluator 評価者の識別子 --dimension 自然さ --dimension 文脈への適合 \
  --identity-label 隠すモデル名
```

比較候補は2〜8件とする。入力・検証範囲・対象契約・反復・注入条件が一致する結果だけを比較する。元ファイルは書き換えず、各実行識別子に対応する元ファイルのSHA-256も保存する。読込み後に既存の証拠型から再出力して全項目を照合し、未知の項目や既存の評価を捨てる復元は拒否する。日時表記も含めて元の書出し形式を要求する。コマンドを中断した場合は評価・対応表を保存しない。別プロセスへの途中評価の復元は行わない。

### 速い状況評価から状態更新への接続

`FastAppraisalCase`に出来事・初期状態・定型評価規則・現在文脈のリビジョン・生成時刻・確定時刻を明示し、`fast_appraisal_target`へ登録する。本番`appraise_event`で作成した候補をそのまま本番`InternalStateReducer.commit`へ渡し、前後の状態と根拠を記録する。該当する規則がなく候補が返らなければ、状態更新は呼び出さない。候補の鮮度・時刻・値の範囲の判定は状態更新側が行う。

各反復で独立した初期状態から開始し、共有の本番状態は更新しない。検証範囲はADJACENT、機械判定はNOT_RUNである。速い経路の公開入口は出来事を受け取り、意味解析結果は受け取らない。意味解析結果から深い状況評価への接続は次節の入口を使う。その後の注意・実行判断への接続は別途製造する。

### 入力意味解析から深い状況評価への接続

`InputMeaningLabCase.appraisal`へ`MeaningAppraisalSettings`を指定し、`input_meaning_target`の`appraisal_bindings`へ`MeaningAppraisalBindings`を渡す。この場合の対象名は`meaning_appraisal`、検証範囲はADJACENTである。型付き入力には`input_meaning`と`appraisal`の二項目で、意味解析の入力と後続の状態・文脈・方針・時刻を保持する。

本番の意味解析が返した`meaning`を加工せず、本番`DeepAppraisalInterpreter.appraise`へ同じ出来事とともに渡す。意味解析が意味を返さなければ後続は呼ばず、元の公開失敗結果を記録する。後続の鮮度照合と候補採用は本番処理が行う。出力は意味解析の公開結果、状況評価への実入力、確定した状況評価候補を含む。現在の状態の更新と注意・実行判断への接続は含まない。

## 身体の結合と記録の可視化

BodyExecutionLabCaseとbody_execution_targetは、本番の身体計画・採用・物理制御・姿勢公開を接続します。BodyRealtimeLabSettingsを指定すると、本番の実時間層も独立して動作します。計画の遅延指定はbody.execution.planning、LLMの指定はbody.planning.llmです。

visualize=Trueを指定した場合、各反復のtyped_outputs.visualization_htmlへ、単独のブラウザーで開けるHTMLを返します。文字列をUTF-8のファイルへ保存して開くと、観測間隔に沿った再生と位置変更ができます。身体モデル、姿勢識別子、状態のリビジョン、観測時刻を表示します。親子関節の座標と末端位置は既存の本番計算から求め、三方向へ平行投影します。表情などの値と合成情報の採用参照も確認できます。

表示は記録済み姿勢の切替えだけを行います。全時点で共通縮尺を使用し、モデルにない関節や動作を補いません。表示する姿勢数はmax_intervals、書出し容量はmax_export_bytesの上限に従い、超過時には切り捨てず失敗します。可視化は検証側の任意出力であり、GUIや本体の稼働条件ではありません。既存の棒人間用接続の命令保持結果やこの記録表示を、実機への適用・人間による品質確認の合格と同一視しません。

### 模擬描画先との隣接検証

BodyExecutionLabCase.avatarへBodyAvatarLabSettingsを指定すると、本番AvatarPresentationRuntimeへ実際の姿勢を投入します。bindingは本番の対応付け、delay_sは模擬描画先の待機秒数、outcomesは公開型による応答列です。応答列を使い切った後は最後の応答を使用します。binding_reloadsには0始まりの姿勢番号と交換後の対応付けを昇順で指定でき、交換は本番reload_bindingへ渡します。

描画先の同期呼出しは専用スレッドで実行し、身体の更新を待たせません。終了時は模擬描画先の待機を解除し、スレッドを回収します。適用報告・呼出しの実測区間・間引き数・最後に適用した命令を記録します。この接続は本番投影と模擬描画先の隣接検証であり、実機の描画接続ではありません。

### 目標・約束の確定から注意への隣接検証

GoalCommitmentLabCase.attentionへGoalAttentionLabSettingsを指定すると、goal_commitment_targetの検証範囲はADJACENTになります。注意の割当方針と、各更新を注意へ引き渡す時点の全体文脈のリビジョンを明示します。目標・約束自身のリビジョンで全体文脈のリビジョンを代用しません。同じ対象登録へ単独検証の条件を混在させることはできません。

本番GoalCommitmentStoreの確定結果に含まれる事実を、本番の目標・約束用の変換処理からAttentionCoordinatorへ渡します。更新が拒否された場合は後続の注意処理を呼びません。事実・入力信号・起動可否・注意の状態・引き渡された判断開始情報を記録します。各反復の状態は独立しています。後続の実行判断や運用中の全体文脈取得はこの隣接検証だけで完成としません。

### 発行済み活動要求の単独検証

ActivityLabCaseに発行済みActivityInvocation、各事前確認へ順番に返すExecutionPreflightSnapshot、実行時刻を指定し、activity_targetへ提供側の公開接続を渡します。activity.preflightとactivity.providerで遅延を注入できます。入力の確認状態が足りない場合は暗黙に以前の状態を再利用せず失敗します。

本番ActivityExecutionCoordinatorとActivityExecutionAuthorityが採用・再確認・実行報告の確定を行い、to_execution_eventが同じ確定結果を出来事へ投影します。検証結果のCOMPLETEDは観測処理の完了を意味し、活動の成否はrecord.result.statusとevent.payload.statusへ残ります。未確認の効果の可能性と確定した効果参照を混同しません。計画から活動要求を作る接続は別の未完経路です。

### 活動結果から定型評価への接続

ActivityLabCase.appraisalへEventAppraisalSettingsを指定するとADJACENTで実行できます。評価規則・初期状態・現在文脈のリビジョン・候補作成時刻・更新時刻を入力に明示し、本番の出来事投影、appraise_event、InternalStateReducerへ順に渡します。単独の出来事評価と同じ接続処理を使用します。規則が一致しなければ状態を更新しません。

後続の評価・状態更新で本番処理が失敗した場合、検証結果はPRODUCT_FAILEDとなりますが、すでに確定した活動のrecordとeventは保持します。appraisal_failure_stageへ失敗段階を記録し、活動の完了や効果参照を消しません。

### 採用済みの過去表現を使う検証

SpeechAdjacentCase.prior_examplesへSpeechPriorExampleを渡します。各例には確定済みCharacterUtterance、対応するSemanticAcceptance、当時の制約を保持します。意味検証でACCEPTEDの例だけを選び、本番prior_realization_from_utteranceで投影します。最大3件、同一意味計画・人物・制約、日時の適格性は本番の入力契約に従います。

過去表現をcharacter_context.prior_realizationsへ直接入れて採用確認を迂回することはできません。生成後は通常と同じ意味検証と発話表現計画へ渡します。検証側は別表現を強制せず、文字列の違いを意味維持や品質の合格条件にしません。実LLMによる反復回避の品質と正式な人間評価は別途確認が必要です。

## 採用待ち中の先行合成

SpeechPreparationSettings.tts_modeをSPECULATIVE_AFTER_PERFORMANCEにすると、発話表現計画の確定後、意味検証の待機中に本番SpeechPreparationOrchestratorの許可を得て合成を開始する。合成結果は同じSpeechRuntimeの候補へ登録する。音声が完成しても採用待ちの候補はPREPARINGを維持し、提示しない。採用時だけ同じ資源参照表と候補を待ち行列・再照合・提示へ継続する。

既に確定している採否を合成予約前に確認し、不採用なら予約しない。待機中に不採用が確定した場合は進行中の合成を取り消し、完成済み音声は本番PreparedAudioDiscarderで破棄する。speculative_tts_limitが0なら先行合成せず、採用後の合成は許可する。schedulingには採用確定前の候補状態と、準備枠・先行合成数・未回収処理数を記録する。

一反復の一候補について模擬音声提供先と模擬提示を使い、採用待ち、採用拒否、取消、上限0、検証が先に終わる場合を確認する。複数候補が共有する上限の負荷検証、長時間動作、実音声の品質は別途必要である。本番側の「合成作業が開始する前の取消で枠が残る」経路は#348のPR #583で修正し、本流51eb22aae42ad90373c66f0c3c7505b336ff9f59へ採用済みである。実音声の品質や長時間運転の完成は、この修正の採用とは別に確認する。

## 配信観測とコメント集中入力

StreamingLabCase.monitorにStreamingMonitorSettingsを渡すと、配信操作と並行して、本番StreamingSubsystemRuntimeへ外部観測とコメントを投入する。StreamingMonitorFrameの列に区間ごとの型付き観測・コメントを指定し、sample_interval_sとcomment_limitを明示する。操作要求を空にして観測だけを検証することもできる。

streaming_targetのmoderatorに本番の審査接続契約を渡せる。streaming.moderationへ遅延・失敗を注入し、配信操作との重なりは実測区間で確認する。審査を渡さない場合の扱いも本番実装に従う。観測期間の終端に未完了の審査があれば、pending_at_window_endへ記録してから終了時に回収する。期間内に全コメントの処理が完了したとは扱わない。

この接続の範囲はISOLATION、機械判定はNOT_RUNである。集中入力・模擬審査・模擬配信操作の確認を、入力意味解析からの配信意思決定、活動実行からの要求構成、注意への代表信号引渡し、実配信の成立へ昇格しない。

## ゲームの継続監視と終了

`GameMonitorCase`へ本番の開始要求、`GameMonitorFrame`の入力列、監視間隔、ゲーム更新間隔、観測保持上限、正常終了か取消かを指定し、`game_monitor_target`へ操作先と戦術選択の公開接続を渡す。開始・戦略更新・観測受理・状態更新・終了は本番の`GameSkillRuntime`が行う。検証側で戦略や操作を推測しない。

各観測区間で更新前後の公開状態、保持された観測、投入件数、締切超過数、未完了処理数、単調時計の観測時刻を記録する。終了時には終了前後の状態、所要時間、取消で不確かになった操作報告、最終未完了処理数を記録する。途中で専用処理が終了した場合は`PRODUCT_FAILED`とし、監視が完了したことだけで正常進行と扱わない。

条件の不一致や記録区間の上限超過は開始前に拒否する。入力のリビジョンの不適合は本番の検査結果を保持し、検証側でリビジョンを付け替えない。観測列の入力時刻と、実測した観測・終了時刻は区別する。

模擬音声合成を実時間で20秒待たせ、1秒ごとの全20区間でゲーム状態の更新を確認した。合成のタイムアウトはこの試験の型付き条件で25秒とし、本番の既定値は変更しない。

範囲は`ISOLATION`、機械判定は`NOT_RUN`。本番の発話経路との並行実行は既存の`parallel_target`で接続し、それぞれの範囲と時系列を保持する。模擬操作先での状態更新・観測容量・戦略更新・終了回収を、実ゲームの品質や会話全体の完成へ昇格しない。この検証は#352の正本第19節の範囲であり、今回の目標の対象外である#586の性能試験・改善には着手しない。


### 実行判断・人物表現の待機とゲーム進行

## 状態と評価事実から実行判断への接続

`MeaningAppraisalSettings.executive` に `AppraisalExecutiveSettings` を指定し、`MeaningAppraisalBindings.executive` へ本番のLLM・現在状態の接続を渡す。`AppraisalStateCommitSettings.facts_revision` を明示し、採用済みPR #587の `InternalStateReducer.commit_with_facts` が返す更新後状態と評価事実を、そのまま `ExecutiveDeliberator.deliberate` へ渡す。元候補の基底のリビジョンを書き換えない。

`context_template` は、出典・文脈のリビジョン・目標のリビジョン・注意のリビジョン・能力・事前条件など周辺の公開型入力を固定する検証用ひな形である。実行時には意味・内部状態・評価事実だけを実際の前段結果へ置き換え、取得時刻を明示された判断時刻とする。出典やリビジョンが前段と合わなければ本番の公開型が拒否する。実行判断の採用は本番の所有者が行い、現在状態と評価事実の双方のリビジョンを再検査する。

意味解析や状態確定が失敗した場合、実行判断を呼ばない。任意の注意接続は実行判断のLLM待機より前に実施する。`executive.llm` で待機・失敗を注入でき、時系列には状態確定と実行判断を別段階として記録する。出力は前後状態、元候補、確定した評価事実、実際の判断入力と確定判断を保持する。範囲は `ADJACENT`、機械判定は `NOT_RUN` であり、実LLMの品質や本体全体の結合を代替しない。


## 振り返り候補と既存記憶の関係指定

`ReflectionMemorySettings.initial_writes` へ公開型の初期書込み要求を渡すと、反復ごとに独立したメモリ内保存先を本番の `MemoryStoreAuthority.write` で準備する。`write_bindings` は提案識別子ごとに対象記憶・期待するリビジョン・関係種別を明示する。採用された候補を変更せず、その条件を既存の `MemoryWriteRequest` に渡す。新規保存の既存経路も保持する。

記憶の更新・拒否・置き換え・矛盾関係の確定は本番の記憶所有者が行う。期待するリビジョンが古い場合は新規記録も関係も追加しない。振り返り側が不採用にした候補には関係指定を適用しない。重複指定や対応する提案結果がない指定を、暗黙の選択・通常の新規保存へ変換しない。初期書込み結果、採用候補、実際の書込み要求と結果、保存先の記録・関係、検索結果を証拠へ保持する。

これは明示した検証入力で本番の書込み判断を通す隣接検証であり、振り返りの関係提案から実運用の書込み条件を自動決定する意味判断ではない。候補や関係提案の内容から検証側が対象を推測しない。メモリ内での成功をPostgreSQLへの永続化・再起動後の保持と扱わない。


## 複数候補の共有準備枠と音声合成

`speech_capacity_target`は一反復につき一組の`SpeechPreparationAdmission`、`CandidateTaskRegistry`、`SpeechPreparationOrchestrator`を作り、複数候補を入力順に同じ所有者へ投入する。`SpeechCapacityCase`には本番の運用方針と、候補ごとの`TTSSynthesisCase`、優先順位、合成方式、意味採用済みかどうかの検証前提を保持する。全入力を出力記録の前提として照合する。

受付・背景枠・先行合成枠の判定は本番所有者が行い、許可された合成だけを本番`TTSProviderAdapter`へ接続する。入力候補識別子と実際の合成要求・結果を併記し、実行・反復・候補ごとに異なる公開音声参照を保持する。受付拒否や先行合成の見送りを、生成成功や提示完了へ変換しない。資源と未完了処理は反復終了時・取消時に回収する。

この入口は準備制御と合成の隣接検証である。生成済み要求と採否の前提を明示入力として使うため、意味検証の判断を実行した証拠ではない。生成からの共有待ち行列、複数候補の提示順と割込み、実音声の品質、全体の長時間運転は別に確認する。機械の品質判定は`NOT_RUN`を保持する。


## 共有待ち行列から複数候補の提示

`speech_queue_target`は`SpeechQueueCase`の複数の準備済み候補を、一反復につき同じ`SpeechRuntime`と`PreparedSpeechQueueCoordinator`へ登録する。候補ごとの運用方針は同一でなければならない。待ち行列の優先順位・容量超過・失効は本番所有者が判断する。取出し後に渡された現在状態の接続から最新状態を読み、本番の`revalidate_current`と既存の提示処理へ進む。

受付結果、実際に読んだ状態、提示報告、候補状態を記録する。先の提示中に状態が変わり、次候補の照合が失敗した場合は、先の完了報告を失わず`PRODUCT_FAILED`と失敗候補を返す。例外本文を記録せず、失敗を採否の成功へ変換しない。取消時は現在の提示処理と残候補・準備済み音声を回収する。一つの音声破棄が例外で失敗しても残候補の破棄と実行基盤の終了を続け、終了失敗を保持する。外部例外の本文は出力しない。

これは準備済み候補を入口とする待ち行列・再照合・提示の隣接検証であり、生成処理からの一貫した結合ではない。提示中の新規候補追加と割込み判断、実音声の品質、長時間運転は残る。運用時刻の初期条件は候補に添えた状態から取得し、その後は実際に読んだ状態の観測時刻へ進める。


## 生成結果を共有実行基盤へ引き継ぐ

`SpeechPreparationSession`は一つの`RunContext`と運用方針に属し、本番の`SpeechRuntime`、準備受付、候補別処理登録、先行合成制御、音声資源表、待ち行列を保持する。`SpeechAdjacentBindings.preparation_session`へ同じ検証実行の共有基盤を返す関数を渡すと、発話生成・意味検証・表現計画の確定結果を同じ所有者へ採用する。記録用JSONを読み戻して候補状態を作り直さない。

複数候補をまとめて待ち行列へ渡す場合は、候補準備の`queue_for_revalidation`を無効にして生成結果を本番所有者へ保持し、その公開候補取得と共有`queue.enqueue_current`を使う。取出し後は本番の現在状態照合と`execute_presentation`を呼ぶ。候補や採否を検証側で捏造しない。実際の生成・意味検証を通った二候補の同一所有者での提示を試験している。

共有基盤を使用する先行合成では、同じ準備受付と先行合成上限を使う。一候補の終了・取消はその候補の登録処理だけを回収し、別候補を停止させない。実行終了時に全体を回収する。他の実行文脈、異なる運用方針、終了済みの共有基盤への接続は拒否する。反復ごとに共有基盤を作り直し、開始時刻には検証入力の観測時刻を渡す。

これは型付き接続と模擬提供先による証拠であり、実LLM・実音声品質や長時間の継続運転の合格ではない。提示中の新規候補投入と割込みの全経路は引き続き確認する。


同じ共有実行基盤で、先の提示中に次の発話の意味生成・人物表現・意味検証・候補確定・待ち行列投入が完了することを確認した。次生成の実測区間が先の提示待機区間内に収まること、提示順を保って次候補を提示できること、取消時に待ち行列と処理を回収することを試験している。任意の割込み方針や実際の可聴音声の品質をこの試験で合格にはしない。
