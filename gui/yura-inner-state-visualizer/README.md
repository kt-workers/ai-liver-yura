# Yura Inner State Visualizer

ゆらの感情・Drive・Activity状態を、光の粒子の色、密度、動き、形状として表示するサイドカーです。
`ai-liver-yura` モノレポの `gui/` 配下で、本体とは別プロセスとして動作します。

## 画面コンセプト

画面名は **「こころの潮流」** とします。
会話画面の「ことばの水面」、配信管理画面の「配信の灯台」と同じく、海を用いた抽象的な命名で統一します。

- ヘッダーには固定の画面名を表示します。
- 現在の感情表現はヘッダーのタイトルとして使用せず、画面下部の `MOOD` に表示します。
- 現在のActivityは画面下部の `NOW` に表示します。

## 起動

```bash
cd ai-liver-yura
.venv/bin/python gui/yura-inner-state-visualizer/server.py
```

ブラウザで <http://127.0.0.1:8765> を開き、その後ゆらを起動します。

感情表現案の比較サンプルは、サーバー起動中に
<http://127.0.0.1:8765/current-concepts.html> で確認できます。

```bash
cd ai-liver-yura
.venv/bin/python -m app
```

ゆらは`127.0.0.1:8766/UDP`へ状態を配信します。ビジュアライザーが起動していなくても、ゆらの動作には影響しません。

## 通信断の判定と画面遷移

- 最後の状態スナップショット受信から **45秒** 更新がない場合に、状態ソースを利用不可として扱います。
- 低周期の状態スナップショットは表示用の状態ベクトルへ補間し、現在の目標へ到達してから次の目標へ進みます。移動中に複数届いた場合は数値を平均した次の目標へまとめ、受信の詰まりによる形状の飛びを抑えます。
- SSE接続自体が切断された場合は、45秒を待たず再接続状態へ移行します。
- 通信断時は各粒子の現在位置と回転速度を引き継ぎ、中心から外向きの一定加速度を加えて約4.2秒で散逸させます。
- 散逸軌道は、回転運動の接線方向を初速、切断瞬間の中心外向きを遠心加速度の方向として計算します。
- 散逸中の粒子は、切断直前のサイズ、光量、色を保持します。
- 状態受信が復帰した場合は、各粒子の現在速度を短く減衰させながら中心へ集め、速度まで連続する曲線で粒子球の回転へ合流させます。
- 背景光は中心付近の粒子密度にだけ連動し、画面外へ散った粒子を追従しません。
- 球体の奥側にある粒子は暗く描画し、前後と回転方向を判別しやすくします。
- 粒子球は負方向へ一定して回転し、arousalは回転方向ではなく回転速度だけを変化させます。
- 感情を表す大小2色の粒子と中心核は、粒子の収束完了後に滑らかに現れます。
- 通信断・復帰アニメーションは、状態値の意味ではなく接続状態を表す演出です。

## 単独確認

別のターミナルで次を実行すると、感情状態を模擬できます。

```bash
.venv/bin/python gui/yura-inner-state-visualizer/simulator.py
```

シミュレーターは`127.0.0.1:8771/UDP`で画面刺激を受信し、Coreと同じ感情評価・状態更新処理を使って反応後のスナップショットを即時配信します。通常時は1秒間隔で状態を配信し、`--interval`で変更できます。

- `tap`: 穏やかな驚きと愉快
- `double_tap`: より強い驚きと愉快
- `long_press`: 喜びを伴う落ち着いた反応
- `drag`: 驚きと愉快を伴う動的な反応

シミュレーターとゆら本体は同じ入力ポートを使用するため、同時には起動しません。ポートを変更する場合は、サーバーの`--input-port`とシミュレーターの`--interaction-port`へ同じ値を指定します。

## 表現の対応

- valence: 基調色となる寒色から暖色への連続的な色相
- mood: 基調色への弱い補正と画面下部の感情名
- arousal: 粒子球の回転速度、呼吸のテンポ、発光
- talkativeness: 粒子表面の流れと気泡が受ける流れ
- curiosity: 全体の広がり
- engagement: 粒子の凝集度
- boredom: ゆっくりした輪郭の緩みと扁平化
- energy: 明るさと粒径
- reactive emotions: 粒子を均等な2群に分け、強い2感情を色、各感情値に応じた粒径、感情種別ごとの微妙な回転速度差で表現
- emotional pressure: 中心核の収縮と発光
- reactive emotion delta: 新しく強まった感情が中心から波として伝播
- joy: 滑らかな膨張と大きな呼吸
- amusement: 弾む非対称な波
- anger: 覚醒度に応じて鋭くなる凹凸
- sadness: ゆっくり沈む扁平化
- fear: 覚醒度に応じて強まる細かな震え
- surprise: 外向きの脈動
- discomfort: 不均一な歪み

平常時は真球に近い静かな形状を保ちます。個別感情は種類ごとに異なる変形として重なり、感情圧だけでは表面を荒らしません。感情圧が怒りまたは恐れと重なった場合は、抑えきれない緊張として輪郭にも現れます。

通信断・復帰時の拡散と収束は接続状態の演出であり、boredomや感情状態を表す散逸ではありません。

## 画面からの刺激

粒子空間へのクリック、ダブルクリック、長押し、ドラッグを、それぞれ`tap`、`double_tap`、`long_press`、`drag`刺激としてCoreへ送ります。canvasへフォーカスしてEnter/Spaceを押した場合は`tap`になります。

- クリックは単発波紋、ダブルクリックは二重波紋として表示します。
- 長押しは押している間に収束する光として表示します。ドラッグ中は軌跡だけを表示して後端から短時間で薄く消し、波紋はボタンを離した位置から広げます。
- 画面は刺激種別、正規化座標、長押し・ドラッグの継続時間だけを送信し、感情値を直接変更しません。
- Coreが`USER_INTERACTION`として受理し、感情・Driveを評価して`STIMULUS_REACTION`を生成します。
- ブラウザ、サーバー、Core入力Adapterでは刺激種別ごとに連打を抑制し、意図したダブルクリックなど別種別の操作は区別します。キュー上では最新の刺激だけを残せるイベントとして扱います。
- 入力本文、会話履歴、ウィンドウ名、キー入力は送信しません。

詳細なデータ形式は[PROTOCOL.md](PROTOCOL.md)を参照してください。
