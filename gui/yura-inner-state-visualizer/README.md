# Yura Inner State Visualizer

ゆらの感情・Drive・Activity状態を、光の粒子の色、密度、動き、形状として表示するサイドカーです。
`ai-liver-yura` モノレポの `gui/` 配下で、本体とは別プロセスとして動作します。

## 画面コンセプト

画面名は **「こころの潮流」** とします。
会話画面の「ことばの水面」、配信管理画面の「配信の灯台」と同じく、海を用いた抽象的な命名で統一します。

- ヘッダーには固定の画面名を表示します。
- 現在の感情表現はヘッダーのタイトルとして使用せず、画面下部の `MOOD` に表示します。
- 現在のActivityは画面下部の `NOW` に表示します。

## 起動

```bash
cd ai-liver-yura
.venv/bin/python gui/yura-inner-state-visualizer/server.py
```

ブラウザで <http://127.0.0.1:8765> を開き、その後ゆらを起動します。

```bash
cd ai-liver-yura
.venv/bin/python -m app
```

ゆらは`127.0.0.1:8766/UDP`へ状態を配信します。ビジュアライザーが起動していなくても、ゆらの動作には影響しません。

## 通信断の判定と画面遷移

- 最後の状態スナップショット受信から **45秒** 更新がない場合に、状態ソースを利用不可として扱います。
- SSE接続自体が切断された場合は、45秒を待たず再接続状態へ移行します。
- 通信断時は各粒子の現在位置と回転速度を引き継ぎ、中心から外向きの一定加速度を加えて約4.2秒で散逸させます。
- 散逸軌道は、回転運動の接線方向を初速、切断瞬間の中心外向きを遠心加速度の方向として計算します。
- 散逸中の粒子は、切断直前のサイズ、光量、色を保持します。
- 状態受信が復帰した場合も、光の粒子を数秒かけて徐々に加速させながら中心へ集めます。
- 背景光は中心付近の粒子密度にだけ連動し、画面外へ散った粒子を追従しません。
- 球体の奥側にある粒子は暗く描画し、前後と回転方向を判別しやすくします。
- 粒子球は負方向へ一定して回転し、arousalは回転方向ではなく回転速度だけを変化させます。
- 感情の潮流と中心核は粒子の収束完了後にフェードインし、状態色も滑らかに遷移します。
- 通信断・復帰アニメーションは、状態値の意味ではなく接続状態を表す演出です。


## 表現の対応

- valence: 寒色から暖色への色相
- mood: 基調色と画面下部の感情名
- arousal: 粒子の速度、脈動、発光
- talkativeness: 表面の流動性
- curiosity: 全体の広がり
- engagement: 粒子の凝集度
- boredom: 形状の扁平化と散逸
- energy: 明るさと粒径
- reactive emotions: 強い2感情を異なる色の潮流として混合
- emotional pressure: 中心核の収縮と発光
- reactive emotion delta: 新しく強まった感情が中心から波として伝播
- 感情の激しさ: 平常時は真球に近い静かな形状を保ち、arousal、感情圧、反応感情、valenceの強さが重なるほど呼吸と表面の乱れが大きくなる

## 画面からの刺激

粒子空間をクリック、またはcanvasへフォーカスしてEnter/Spaceを押すと、穏やかな`tap`刺激をCoreへ送ります。

- 画面は刺激種別と正規化座標だけを送信し、感情値を直接変更しません。
- Coreが`USER_INTERACTION`として受理し、感情・Driveを評価して`STIMULUS_REACTION`を生成します。
- ブラウザ、サーバー、Core入力Adapterで連打を抑制し、キュー上では最新の刺激だけを残せるイベントとして扱います。
- 入力本文、会話履歴、ウィンドウ名、キー入力は送信しません。

詳細なデータ形式は[PROTOCOL.md](PROTOCOL.md)を参照してください。
