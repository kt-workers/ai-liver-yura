# 独立AIレビュー実行時のSHA固定と再実行記録

対象Issue: #371

## 目的

独立AIレビューの実行開始時に対象としたPR先端SHAと、実際にレビューしたSHA、GitHubへ状態を書き込むSHAを必ず一致させる。

また、同じPR先端SHAに対して一時的なレビュー不能から回復して再実行した場合、新しいレビュー結果を監査履歴へ正しく残せるようにする。

## 実行開始時SHAの固定

GitHub制御系がイベントから取得したPR先端SHAを、そのレビュー実行の `expected_head_sha` とする。

レビュー実行基盤は次を必須とする。

1. 実行開始前にGitHub上の現在PR先端SHAが `expected_head_sha` と一致することを確認する。
2. レビュー入力を構築するためにPRを再取得した時点でも、取得した先端SHAが `expected_head_sha` と一致しなければ停止する。
3. レビュー担当AIへ渡す `ReviewTarget.head_sha` は `expected_head_sha` と一致しなければならない。
4. レビュー担当AIの応答後、公開直前に現在PR先端SHAを再取得し、`expected_head_sha` と一致しなければ結果を公開しない。
5. GitHubへ最終状態を書き込む前に、信頼済み `ReviewDecision.reviewed_head_sha` が `expected_head_sha` と一致することを再確認する。
6. 同じ最終境界で、レビュー開始時の `authority_generation` とGitHub liveから再構築したReviewContextの世代が完全一致することを再確認する。

これにより、実行開始時A、レビュー入力構築時Bのような競合が起きても、Bをレビューした結果をAの状態として書き込むことを禁止する。

PR先端が変化した場合は古い実行をレビュー不能として終了し、新しいPR更新イベントが新しいSHAのレビューを開始する。

## レビュー循環識別子

レビューコメントの重複防止は、同じ実行を二重公開しないための仕組みであり、同じSHAに対する将来の正当な再実行を抑止してはならない。

循環識別子には少なくとも次を含める。

- PR番号
- レビュー対象SHA
- レビュー担当AI識別子
- レビュー実行識別子

レビュー実行識別子はGitHub Actions実行ID、試行回数、対象SHAを含む信頼済み値とする。

同一実行識別子の二重公開は拒否する。
異なる実行識別子であれば、同じSHAでも新しいレビュー循環として記録できる。

これにより、例えば一時的なGemini障害による `BLOCKED` の後、障害解消後の再実行で `PASS` した場合に、古いレビュー不能コメントだけが残って対象SHAの状態だけ成功へ変わる監査不整合を防ぐ。

## 不変条件

- レビュー対象SHAと状態書込先SHAを分離しない。
- 最終状態は、開始時と同じAuthority世代にだけ書き込む。
- PR先端移動を追従して同一実行内で別SHAのレビューへ切り替えない。
- 古い実行から現在SHAへの合格を発行しない。
- 同一実行の重複コメントを作らない。
- 同じSHAであっても別実行の正当な回復結果を記録できる。
- 再実行によって過去結果を削除・上書きせず、監査履歴として残す。

## 検証

単体・偽結合試験で次を確認する。

1. 事前確認後、レビュー入力構築前にPR先端がAからBへ動いた場合、レビュー担当AIを呼び出さず停止する。
2. レビュー担当AI実行中にAからBへ動いた場合、結果を公開しない。
3. `ReviewDecision.reviewed_head_sha` が実行開始時SHAと異なる場合、最終状態を書き込まない。
4. PRコメント公開後から最終状態書込前にAuthority世代が変化した場合、`success` / `failure`を状態として書き込まない。
5. 同じPR・同じSHA・同じレビュー実行識別子は1回だけ公開する。
6. 同じPR・同じSHAでもレビュー実行識別子が異なる場合は別の監査記録として公開できる。
7. 一時的なレビュー不能の後の再実行合格が、古い重複防止キーによって抑止されない。
