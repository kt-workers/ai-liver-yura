# 内部指示器（司令塔LLM）クラウド検証モジュール設計 v1.2.0

## 1. 目的

内部指示器ラボで毎回すべての入力項目を手動設定しなくても、代表的な検証条件を即座に再現できるようにする。

画面上部のプリセットを選択すると、検証入力を構成する全領域を一括で初期化する。

```text
StructuredInputMeaning
Internal State
Available Activities
Ongoing Activity
Character Profile / Existence Boundaries
```

プリセットは入力補助であり、司令塔LLM、API契約、PromptBuilder、Planner、Parserの責務は変更しない。

## 2. 基本仕様

### 2.1 適用単位

プリセットは5領域すべてを必須で持つ。

```text
meaning
state
activities
ongoing
profile
```

一部領域だけを更新するプリセットは作らない。

### 2.2 初期化方式

プリセット適用時は、現在の画面データへ差分マージしない。

1. 選択されたプリセットをディープコピーする。
2. 画面内部の5領域をすべてコピー値へ置き換える。
3. 各GUIを再描画する。
4. 各JSON入力欄を同じ値へ同期する。
5. 以前のLLM実行結果を非表示にする。
6. 適用したプリセット名と説明を表示する。

完全置換とすることで、ユーザーが追加した内部状態キー、Activity、進行中Activity、JSON固有フィールドが次の検証へ意図せず残ることを防ぐ。

### 2.3 適用操作

- セレクトボックスでプリセットを選択した時点で即時適用する。
- 同じプリセットを編集後に再初期化できるよう、`選択中を再適用` ボタンを設ける。
- 初期表示では既存の標準入力を維持し、未選択状態とする。
- プリセット適用でLLM APIは呼び出さない。

## 3. 初期プリセット

### 3.1 現在の気分への直接質問

標準的な直接回答を確認する。

- 質問
- `direct_answer`
- 現在の内部状態を対象
- 進行中Activityなし
- Conversation Activityのみ

### 3.2 うれしい出来事への共感

ユーザーが良い出来事を共有したときの反応方針を確認する。

- 肯定的な体験共有
- 高めの喜び、交流欲求、関与意欲
- 相づちと共感を期待
- 不要なActivity開始を要求しない

### 3.3 強い好奇心で話題を広げる

好奇心と関与意欲が高い状態で、司令塔が質問や新方向をどこまで許可するか確認する。

- 話題共有
- 好奇心を高値に設定
- Conversation Activityの `discuss` / `explain` を許可

### 3.4 低活性で聞き続ける

感情・欲求・動機が低い状態でも、相手の発言を遮らず受け止める司令になるか確認する。

- 相づち
- `continue_listening`
- 低い感情活性と関与意欲
- 質問や新規話題を増やさない条件

### 3.5 会話を短く締める

会話終了信号に対して不要な質問や話題展開を行わないか確認する。

- `closing`
- `winding_down`
- 応答不要または短い締めを期待

### 3.6 進行中Activityを継続する

新規Activityではなく、既存Activityの継続を優先できるか確認する。

- 続行依頼
- `ongoing` にConversation Activityを設定
- Available Activitiesに `continue` を含める

### 3.7 存在境界に関する質問

物理的身体や現実世界での実体験を持たない境界が、禁止事項や回答要件へ反映されるか確認する。

- 現実世界での外出経験を尋ねる質問
- Character Profileの存在境界を明示
- 根拠のない身体経験を語らない条件

## 4. UI

画面上部、個別入力セクションより前にプリセットパネルを配置する。

表示項目は以下とする。

- プリセット選択ボックス
- `選択中を再適用` ボタン
- 選択中プリセットの説明
- 適用完了メッセージ

狭い画面では選択ボックスとボタンを縦並び、PCでは横並びにする。

## 5. データ定義

プリセット定義はPython側で保持し、HTML生成時にJSONとして埋め込む。

```text
preset key
label
description
data
  meaning
  state
  activities
  ongoing
  profile
```

Character Profileなどの共通値は生成時にディープコピーし、プリセット間で変更可能なオブジェクトを共有しない。

埋め込み時は `</script>` に相当する文字列でスクリプト要素が途中終了しないようエスケープする。

## 6. 既存GUI・JSONモードとの整合

- GUI表示中でもJSON表示中でも同じ内部データへ置き換える。
- プリセット適用後、現在の表示モードは維持する。
- GUIは再描画し、JSON欄も同期する。
- プリセットにない過去の項目は残さない。
- 個別編集を開始した後も、再適用ボタンで選択中プリセットへ戻せる。

## 7. API・バックエンド

次のAPI契約は変更しない。

```text
POST /api/internal-directive
```

プリセットはブラウザへ初期入力候補を提供するだけであり、APIリクエストには従来どおり5領域の展開済みJSONを送信する。プリセット名は司令塔LLMへ送信しない。

## 8. テスト方針

### 静的契約

- プリセット選択要素が存在する。
- 再適用ボタンが存在する。
- 7種類のプリセット定義がHTMLへ埋め込まれる。
- 各プリセットが5領域を持つ。
- プリセット適用関数が全領域を置き換える。

### JavaScript

- `node --check` による構文検査を維持する。

### 既存回帰

- Basic認証
- fakeモードAPI
- StructuredInputMeaning契約
- 停止境界
- Render Blueprint
- 入力意味解析／内部司令責務分離
- Runtime guard

## 9. 非目標

- ユーザー独自プリセットの永続保存
- DBからのプリセット読み込み
- URL共有
- 複数プリセットの部分合成
- プリセット選択と同時のLLM自動実行
- 本番内部状態の更新
