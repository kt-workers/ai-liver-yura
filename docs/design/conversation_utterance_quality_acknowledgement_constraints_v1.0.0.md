# 会話セリフ品質：短い相槌・同意入力の発話制約 v1.0.0

## 1. 背景

実プロセス評価で、ユーザーが短い相槌や同意だけを返した場合にも、Character LLMが直前の発話内容を長く言い換え、会話を先回りして広げる事象を確認した。

代表例:

```text
user: そうだね
assistant: 直前に説明した内容を別の言葉で繰り返し、さらに話題を展開する

user: いいね。そういうの
assistant: 同意への短い反応ではなく、前の内容を再説明する
```

短い相槌は新しい情報要求や話題追加ではない。ここで毎回説明・質問・自己開示を行うと、会話のテンポが重くなり、同じ意味の反復が増える。

## 2. 原因

Response Content PlanはDesire・Motivation・Moralの観測値から生成されるため、ユーザー入力が短い相槌だけである場合でも、次のような展開方針を保持し得る。

- 質問する
- 関連話題を広げる
- 短い自己開示を行う

また、`initiative_level`は応答側の主体性を示すが、相槌入力そのものの情報量を直接表さない。したがって、通常の主体性を持つ会話でも、相槌入力に対する最終的な発話縮退が必要である。

## 3. 設計方針

### 3.1 責務境界

短い相槌・同意入力の判定と発話縮退は、Character Prompt生成直前の発話表現境界で行う。

本工程では次を変更しない。

- Drive Stateの更新式
- Emotion Stateの更新式
- Desire・Motivation・Moralの評価
- Situation Evaluatorの確定結果
- Activity選択
- 接触反応

これにより、内的状態モデルの妥当性評価と、セリフ品質の改善を分離する。

### 3.2 相槌入力の判定

入力をUnicode NFKCで正規化し、前後空白と句読点区切りを処理したうえで、既知の短い相槌句だけから構成される場合を対象とする。

対象例:

```text
うん
うんうん
そうだね
なるほど
いいね
わかるよ
前向きでいいね
いいね。そういうの
```

対象外例:

```text
そうだね。でもゲームは難しい方が好き
いいね。どこから始める？
```

保守条件:

- 疑問符を含む入力は対象外
- 32文字を超える入力は対象外
- 句読点で分割した有効句が3件以上ある場合は対象外
- 既知の相槌句以外を1件でも含む場合は対象外

### 3.3 Response Content Planの縮退

短い相槌・同意入力と判定した場合、元のPlanを変更せず、Character Prompt生成直前の実効Planを次へ縮退する。

- `question_budget=0`
- `new_direction_budget=0`
- `self_disclosure_level=none`
- 質問戦略を除外
- 新話題展開戦略を除外
- 自己開示戦略を除外
- `acknowledge_other`を最低1件保持
- 理由へ`acknowledgement_input_constrained`を追加

許可する戦略は次に限定する。

- `acknowledge_other`
- `continue_conversation`
- `observe_before_speaking`
- `share_reaction`

### 3.4 Character Promptの明示制約

BudgetだけではLLMが意味的な展開を行う可能性があるため、次を明示する。

- 受け止めや小さな反応を示す短い1文だけを返す
- 直前の発話内容を別の言葉で要約・復唱・説明し直さない
- 質問しない
- 自己開示しない
- 新しい話題を始めない
- 追加提案を行わない
- 会話を無理に広げない

## 4. 低主体性挨拶との優先順位

低主体性の挨拶制約を先に評価する。

```text
1. 低主体性の挨拶
2. 短い相槌・同意入力
3. その他の低主体性応答
4. 通常応答
```

これにより、挨拶専用の短い返礼契約を維持しつつ、通常会話中の相槌にも独立した縮退を適用する。

## 5. 回帰テスト

次を固定する。

1. `いいね。そういうの`を短い複合相槌として判定する
2. `前向きでいいね`を短い同意として判定する
3. 実質的な続きや質問を含む入力は相槌扱いしない
4. 通常主体性でも相槌入力なら質問・新話題・自己開示を無効にする
5. 実質的な入力では元のPlanを維持する
6. Character Promptへ意味的復唱禁止と短文制約を出力する
7. 既存の低主体性挨拶制約を維持する

## 6. 実動作評価

修正後は、同一プロセスで次を連続入力して確認する。

```text
そうだね
うんうん
いいね
わかるよ
前向きでいいね
いいね。そういうの
```

確認項目:

- 応答が短い反応に留まる
- 直前発話の意味的な言い換えを行わない
- 質問しない
- 新しい話題を開始しない
- 自己開示しない
- Validatorによる再生成を必要としない

## 7. 後続課題

次は別工程として扱う。

- `今日はゲームする？`のような直接質問への直接回答性
- `何がしたい？`に対する明確な選好表明
- 複数ターンにまたがる一般的な意味的反復
- 相槌の複合表現をDrive State更新でどう分類するか
- 自律発話の話題反復
