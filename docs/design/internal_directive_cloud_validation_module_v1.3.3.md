# 内部指示器クラウド検証モジュール設計 v1.3.3

## 1. 目的

複数プリセットをまとめて実行した結果を基に、検証条件と画面配置を改善する。

対象:

- 「強い好奇心で話題を広げる」プリセット
- 検証データExportパネルの表示位置

## 2. 強い好奇心プリセット

従来のプリセットは全体的な`drive.curiosity`と`engagement`だけが高く、対象別関心や具体的なKnowledge Gapを持っていなかった。

Core方針では全体好奇心だけで質問を許可しないため、従来条件では`listen`となるのが正しかった。プリセット名どおりの条件を検証するため、現在の対象と一致する`related_knowledge`を追加する。

```json
{
  "target_type": "topic",
  "target_id": "deep_sea_unknown_life",
  "interest": 0.94,
  "known_facts": [
    "深海には未分類の生物が多く存在する"
  ],
  "knowledge_gaps": [
    "未発見生物が多いと考えられている深度や環境"
  ]
}
```

このプリセットで確認する内容:

- 全体好奇心だけではなく、対象別関心と既存Gapを根拠にする
- 現在対象を掘り下げる関連質問を1件だけ許可する
- 無関係な新規話題へは展開しない
- 既存Gapを新規Gapとして作り直さない

## 3. Exportパネル配置

従来はExportパネルを最初の入力セクションより前へ挿入していた。

変更後の順序:

1. プリセットと入力条件
2. 「司令塔LLMを実行」ボタン
3. 検証データExportパネル
4. LLM実行結果

Exportは実行済み結果を保存する操作であるため、実行ボタンの直後へ配置する。

完成HTMLでは次のDOM順序を保証する。

```text
#run
  < #transferPanel
  < #resultPanel
```

## 4. 実装方針

- ベースHTML内の実行パネルを明示的なマーカーとして検出する
- 実行パネルの直後へExportパネルを1回だけ挿入する
- マーカーが見つからない場合は黙って誤配置せず、HTML組み立て時に失敗させる
- reviewedモジュールによる存在境界修正と初期折りたたみを適用しても配置を維持する

## 5. 互換性

- Export内容とファイル名は変更しない
- Exportのクリック処理は変更しない
- 折りたたみ機能は変更しない
- API、認証、Render起動先は変更しない
- プリセット数は7件のまま

## 6. テスト

次を画面契約テストで固定する。

- 高好奇心プリセットの対象と`related_knowledge`の対象が一致する
- 対象別関心が設定されている
- 具体的なKnowledge Gapが存在する
- Workspace完成HTMLで`run < transferPanel < resultPanel`となる
- Reviewed完成HTMLでも同じ配置を維持する
- Exportパネルとボタンが重複しない
